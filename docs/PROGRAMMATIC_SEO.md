# 가이드 페이지(프로그래매틱 SEO) 파이프라인

검색으로 찾아올 착지 페이지를 룰셋에서 생성한다. 프론트엔드는 SPA라 URL로 주소 지정
가능한 페이지가 `/` 하나뿐이었고, "국가기관 용역 5억원 계약방법"으로 검색해 도달할
문서가 없었다. 생성기는 `tools/build_seo_pages.py`, 산출물은 `frontend/public/g/*.html`.

## 파이프라인

```bash
python3 tools/build_seo_pages.py          # 생성 (public/g/*.html + public/sitemap.xml)
python3 tools/build_seo_pages.py --check --strict   # 쓰지 않고 게이트만 (CI가 이걸 돌린다)
cd frontend && npm run build              # dist로 복사 = 라이브 반영 (백엔드 재시작 불필요)
python3 tools/indexnow_ping.py --verify-live       # 색인 제출 (라이브 확인 후에만)
```

배포에 nginx·CF Worker·백엔드 변경은 필요 없다. `backend/main.py`의 catch-all이
`dist/` 아래 실제 파일이면 그대로 서빙한다. URL에 `.html`을 붙이는 이유도 그것이다 —
`/g/foo/`(트레일링 슬래시)나 확장자 없는 경로는 그 catch-all이 파일로 인식하지 못해
SPA로 폴백한다.

## 불변식 — 왜 그냥 템플릿을 돌리지 않는가

생성 페이지는 랜딩·제안서와 같은 **대외 주장**이다. 틀린 요율 하나가 감사 현장에
그대로 전달되고, 페이지는 사람이 한 장씩 검수하지 않는다. 그래서 생성기 자신이
게이트를 갖는다(`Builder.gate()` + `tests/unit/test_seo_pages.py`).

1. **밴드 일관성** — 페이지는 "5억원 이상 10억원 미만이면 하한율 85.495%"처럼 구간
   전체에 대한 주장을 한다. 그래서 구간 안 3점(하단·중간·상단)을 실제로 판정해 값이
   같은지 확인하고, 흔들리면 그 밴드를 발행하지 않는다.
   - 실측으로 잡힌 것 ①: 룰 `conditions`의 임계값만 모으면 용역 4억~7.1억이 한 밴드가
     되는데 하한율은 **5억에서 86.745%→85.495%로 바뀐다**(5억은 `pass_score_by_amount`
     키에만 있는 경계). 커밋 8151f15가 고친 P0(같은 질의에 87.495%와 89.745%가 함께
     나온 사고)의 페이지판 재발이었다.
   - 실측으로 잡힌 것 ②: `estimated_price_lte: 4억` 룰은 **400,000,001원**에서 판정이
     바뀐다. 경계를 T로만 잡으면 밴드 첫 금액만 소액수의고 나머지는 일반경쟁인 페이지가
     만들어진다(룰엔진이 2026-07-31에 고친 '초과 vs 이상'과 같은 계열의 실수).
2. **판정의 진실원은 라이브와 같은 코드** — 페이지 숫자를 생성기가 다시 계산하지 않고
   `RuleEngine.match()` / `get_pass_score()` / `build_decision_pack()`을 호출한다.
   랜딩↔라이브 불일치가 구조적으로 불가능해진다.
   ※ 공개 GET `/api/v1/rules-public/list`는 `pass_score_ref`를 해석하지 않아
   CST_001·CST_006·CST_007·SVC_001의 요율이 **null**로 나온다. 그 경로로 페이지를 뽑으면
   요율이 빈칸이 된다 — 반드시 엔진 경유.
3. **근거 없으면 생성 거부** — `legal_basis`가 빈 룰로는 페이지를 만들지 않는다.
4. **못 실은 것을 공시** — 조문 전문은 페이지당 4건까지만 싣는다. 그 사실과, 전문을
   붙이지 못한 근거(예규·세부기준·고시)를 페이지에 적는다. 총계를 숨기면 "인용된 근거 =
   여기 실린 조문 전부"로 읽힌다.
5. **금지 표현 게이트** — `docs/POSITIONING.md`가 금지한 표현("자동 판정", "검증됨",
   체감 수치)이 생성물에 있으면 빌드가 실패한다. 면책 문구는 README와 같은 문구를 쓴다.
6. **ASCII 슬러그** — 한글 URL이 CF Worker→nginx→uvicorn 3단에서 퍼센트 인코딩을
   보존하는지는 라이브에 올리기 전에 검증할 수 없다. 검증 못 하는 것을 대외 URL로
   박제하지 않는다. 한글 키워드는 title·h1·description에 넣는다.

## 일부러 발행하지 않는 것 (근거 부재 — 못 봄 ≠ 없음)

- **지자체 낙찰하한율 상세**: `rules/local_award_criteria.json`은 레코드에
  `"공종": "확인필요"`, `"주의": "…별표 대조 필요(구현단계)"`가 박힌 미완성 자료이고
  런타임 소비처가 없다. 요율 페이지의 근거가 아니다. (지자체 페이지는 계약방법까지만)
- **부정당업자 제재 판정**: 룰엔진 판정 대상이 아니다(POSITIONING §4-4). 제재기준 별표
  원문 XML은 `.gitignore` 대상이라 공개 리포에 없다. 그래서 판정 페이지 대신 근거 조회
  안내 1건만 낸다.

## 룰셋이 바뀌면

`rules/contract_rules.json`·`data/glossary.json`이 개정되면 생성기를 다시 돌린다.
페이지 본문·요율·밴드 경계가 전부 룰셋에서 파생되므로 수기 편집하지 마라 — 다음 생성에서
덮어쓰인다. 페이지 수가 크게 변하면 `test_page_count_reasonable`이 알려준다.
