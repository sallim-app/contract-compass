## 1. 타깃

**공공기관 계약 실무 담당자(신입·순환보직), 계약방법 결정·하한율·부정당 판단을 규정 원문 뒤져 확인 — 실수하면 감사 대상.**

- 정본은 `/data/ops/GROWTH.md` "고객 가설(PMF)" 표의 "계약나침반" 행이다. 이 문서는 그 한 줄의 **전개이지 사본이 아니다** — 표가 갱신되면 이 문서가 따라간다(역방향 금지).
- 정본 행 요약: 대체재=선배에게 묻기·나라장터 검색·조달청 콜센터 / 성공신호=주간 재방문 사용자 ≥3 / 반증조건=무료여도 재방문 0 지속 / 근거=[실측] 원형 파일럿 누적 66명·전환 20%.
- 2차 타깃(파생): AI 에이전트(Claude·ChatGPT·Cursor)에 공공계약 판단 근거를 물리려는 개발자 — MCP 서버가 이 경로다. [추정] 외부 순호출 미검증.

## 2. 문제 — 실무 장면 3개

원형은 공공기관 사내 원형(비공개 파일럿 — 누적 66명/1,393건 사용·종합 전환 20.0% [실측])이다. 아래 장면은 그 리포의 실측 문서에서 왔다.

1. **결정의견서를 매번 수작업으로 쓴다.** 원형 파일럿 실측(현장 10년차 증언): 발주 담당 인력 소수가 조직 전체의 계약 의뢰(연 수천 건)를 나눠 처리 — 담당자 1인당 연 수 건의 계약방법 결정의견서를 100% 수작업 작성. 시간을 아끼려 전임자·타 부서의 유사 문서를 복사해 일부만 고치고, **과거 문서의 잘못된 기준이 스크리닝 없이 그대로 복제**된다. 
2. **법령이 매년 바뀌는데 대조는 사람이 한다.** 국가계약법·계약예규가 매년 개정된다. 비슷한 사업이라도 담당자가 매번 최신 법령을 찾아 수작업 검증해야 하고, 미숙지로 인한 규정 위반 리스크가 상존한다. 신입·순환보직자는 "지금 시행 중인 조문"과 "계약 당시 시행되던 조문"조차 구분하기 어렵다. 
3. **실수하면 감사 지적이다.** 실제 감사 사례(감사원·특정감사 채록, `docs/contract_audit_requirements.md`): 수선 필요 없는 시설물을 수의로 개·보수, 단일 공사를 돌연 분할해 "수의계약 하려고 사업 쪼개기", 무등록업체와 수의계약. 계약방법 선택 하나가 감사 대상이 되므로 담당자는 **조문 근거를 붙여야 안심**한다 — 답만 주고 근거를 안 주는 도구는 이 장면에서 쓸 수 없다.

## 3. 대체재 — 실물 채록 (2026-08-05 조회)

전부 실제로 열어 관찰한 것만 적었다(조회 URL은 각 항목에). 정본 표의 대체재 중 "선배에게 묻기"는 웹 채록이 불가능해 제외 — 콘텐츠에서 이 항목을 다룰 땐 §2의 원형 파일럿 실측(전임자 문서 복사 답습)까지만 근거로 쓸 것.

### 3-1. 나라장터(g2b.go.kr) — 거래 처리 시스템이지 규정 Q&A가 아니다
- **주는 것**: 발주·입찰·계약 등 14개 업무 메뉴(SPA 번들 내 메뉴 트리 487노드 확인). 규정 관련 메뉴는 존재한다 — 고객센터>법령 정보>해석사례 조회·법령정보조회, FAQ, 챗봇.
- **못 주는 것(관찰)**: ①로그인 전 서버 렌더 본문이 사실상 0(가시 텍스트 "나라장터" 4자) — 검색엔진으로 규정 답을 찾을 때 후보에 못 오른다. ②실무자 질문을 메뉴에 대보면: "수의계약"이 메뉴명 487개 중 0건, "적격심사"는 특정 입찰 건의 *결과 조회*뿐(하한율 규정·산식 아님). ③규정 화면 딥링크 3/3 오류 — 동료에게 링크로 못 넘긴다. ④새 규정 질의를 접수하는 메뉴 없음(과거 해석사례 열람만).
- 미확인(추정 금지): 로그인 후 해석사례 화면·통합검색·챗봇의 실제 품질.

### 3-2. 조달청 콜센터·질의 채널 — 답은 오지만 "국가계약법에 한하여, 법적 효력 없이, 일반론으로"
- **주는 것**: 콜센터 1588-0800(평일 09~18시, 공표 상담 범위는 "나라장터 이용절차"), 계약법규질의는 국민신문고 경유(공표 처리기한: 법령 질의 14일·법령 외 7일, 근무일 기준), 해석사례 DB 1,956건 검색(pps.go.kr).
- **못 주는 것(회신 원문 3건 확보·본선 재검증 완료)**: ①**국가계약법 한정** — "조달청은 국가계약법령과 관련한 질의에 한하여 회신"(회신 정형 문구), 지방계약법 질의는 행정안전부 관할이라고 안내 페이지에 명시 → 지자체 실무자는 이 채널에서 답이 안 나온다. ②**내 사안에 적용해 주지 않음** — "구체적인 사실관계 등을 종합적으로 고려하여 **발주기관이 판단할 사항**"(bbsSeq 2503310009, 재검증). ③**법적 효력 없음** — 확인한 3건 전부 말미에 "본 상담(답변) 내용은 법적인 효력을 갖지 아니합니다"(재검증). ④해석사례 상세의 `관련법령` 필드가 확인 3건 모두 공란 — 근거 조항이 구조화돼 있지 않고 본문 문장에만 섞여 있다. ⑤접수일 미표기라 실측 소요일 확인 불가.
- 미확인: 콜센터가 전화로 규정 해석 상담을 실제 해주는지(전화 미실시).

### 3-3. 실무 서적·블로그 — 일반론은 주고, 기준일·내 사안은 편차가 크다
- **주는 것**: 좋은 곳은 꽤 좋다 — silmu.kr은 조문을 항·호·목까지 인용하고 "2026.06.05 기준 법령 반영"을 명시(재검증). 서적(예: 『지방예산회계와 계약법(2025)』 816쪽)은 체계적 해설 제공.
- **못 주는 것(관찰)**: ①**기준일 표기가 매체마다 갈린다** — cliwant·bidpro·조달청 PQ 페이지는 기준일 자체가 없어 최신 여부 판별 불가. 낙찰하한율은 2026-01-30 시행 개정으로 수치가 실제로 바뀌었는데, 기준일 없는 페이지는 어느 쪽인지 독자가 알 수 없다. ②약속한 핵심 수치가 빠져 있어도 모른다 — "2026년 수의계약 금액 한도(최신 기준)" 제목의 글에 정작 표가 없음(HTML `<table>` 0개, 재검증). ③가장 정밀한 블로그도 "법률 자문·공식 유권해석 아님" 면책이며 기관 유형별 차이 미명시. ④서적은 출간 시점에 고정(확인한 대표 해설서는 2015년판·품절).

### 세 채널의 공통 공백 (관찰 근거 있음)
① 지방계약법 질의는 공식 채널이 명시적으로 관할 밖 ② 어느 채널도 "내 사안"에 적용해 주지 않음(공식 채널은 명문으로 거부) ③ 답의 **기준 시점**을 알 수 있는 곳이 드묾(해석사례 관련법령 공란·블로그 기준일 미표기).

## 4. 차별점 — 대체재가 실제로 못 하는 것만

이 리포의 실물에서 확인한 것만 적는다. (확인일 2026-08-05, 실측 = 서버 코드·룰셋 파일 직접 확인)

1. **[실측] 결정론 룰엔진 — 같은 입력이면 항상 같은 판정.** `rules/contract_rules.json` 105룰(2026-08-05 실측; 국가기관/지자체/공기업·준정부 3개 기관유형 분리, 지자체는 LOCAL_* 룰·`local_law_pack`이 별도 수치 적용 — §3 공통 공백 ①"지방계약법은 조달청 관할 밖"을 정면으로 메운다). 계약방법 판정에 LLM을 쓰지 않으므로 환각이 원리적으로 없다 — LLM은 웹 챗봇 설명에만 쓰고, MCP 도구 8종은 전부 무LLM(`mcp/server.py`). §3 채록의 세 채널 모두 "내 사안"(계약유형·추정가격·기관유형·수의 사유)을 넣고 후보를 받는 판정기가 아니었다 — 공식 채널은 명문으로 거부한다(§3-2 ②).
2. **[실측] 조문 인용이 룰에 내장.** 룰마다 `legal_basis`(예: "국가계약법 제4조", "기획재정부고시 제2024-42호")·`source`가 붙어 있고 API·MCP 응답에 그대로 노출된다(`backend/models/response.py`, `mcp/server.py` decide_contract_method). "답 + 붙여 쓸 수 있는 조문 근거"가 한 번에 나온다 — §2-3의 감사 장면이 요구하는 형태.
3. **[실측] 적격심사 통과점수·낙찰하한율까지 산정 파라미터 제시.** 룰 결과에 금액구간별 `pass_score`·`lower_limit_rate`(예: 기술용역 10억 이상 92점/79.995%)·해당 별표 참조가 동봉된다(`rules/contract_rules.json` pass_score_by_amount). 단, 발주기관별 세부기준에 따라 다를 수 있다는 주의를 함께 노출한다(과장 금지 — 이 단서를 콘텐츠에서 떼지 마라).
4. **[실측] 부정당 판단의 근거 조회 — 판정이 아니라 조회다.** 부정당업자 제재는 룰엔진 판정 대상이 아니고, 제재기준 별표(별표2) 청크를 포함한 코퍼스 검색(`search_references`)과 law.go.kr 실시간 판례·법령해석례(`search_cases`/`get_case`)로 근거를 준다. 콘텐츠에서 "부정당 자동 판정"이라고 쓰면 과장이다 — "부정당 제재 기준·판례를 조문 단위로 찾아준다"까지만.
5. **[실측] 기준 시점이 답에 붙는다 — 현행/행위시법 분리 조회.** `get_law_article`은 항상 현행, `get_law_article_asof`는 특정 날짜에 시행 중이던 조문을 조회한다(과거 계약·처분·감사 대응 — 현행 조문을 과거 사건에 적용하면 조용히 틀린다). §3 공통 공백 ③(기준 시점을 알 수 없는 답)의 반대편이다.
6. **[실측] AI 에이전트에 직접 물린다 — MCP 도구 8종.** decide_contract_method / search_law / get_law_article / get_law_article_asof / search_references / search_cases / get_case / report_issue (`mcp/server.py`, 원격 `https://contract.sallim.app/mcp`, 무료 IP당 50콜/일). 검색 0건이면 0건이라고 힌트와 함께 정직 공시하고, 조문 미정비 상호인용은 `notes`로 경고한다 — "못 봄 ≠ 없음" 인식 경계 계약(회사 기치).
7. **[추정] 신입·순환보직자의 시간 절약.** 원형 파일럿 사용 실적(66명/1,393건)은 원형의 실측이지만, 범용판(계약나침반) 외부 사용자의 시간 절약·재방문은 아직 미검증이다. 콘텐츠에서 "○분 절약" 류 수치를 만들지 마라.

**하지 않는 것(정직 공시):** 법적 자문·유권해석이 아니다(README 면책 동일 문구 유지). 발주기관별 세부기준·최신 개정에 따라 다를 수 있으므로 최종 확인은 소속 기관 계약 부서 몫이다.

## 5. 메시지

**한 줄:** "계약방법·하한율, 조문 근거까지 한 번에 — 공공계약 판단의 나침반."

지지 3문장:
1. 계약유형·추정가격·기관유형을 넣으면 룰엔진이 적용 가능한 계약방법 후보와 법령 근거를 결정론으로 제시한다 — 같은 입력엔 항상 같은 답. [실측]
2. 적격심사 통과점수·낙찰하한율, 부정당 제재기준·판례까지 조문·별표 단위로 찾아준다 — 감사 대비에 필요한 건 답이 아니라 근거다. [실측]
3. Claude·ChatGPT·Cursor에 MCP로 바로 물린다 — AI가 지어내는 대신, 이 서버가 검증 가능한 법령 근거를 준다. [실측]

채널별 적용:
- **레지스트리 설명문**: 한 줄 + 지지 3(MCP 관점 우선: 무LLM 도구 8종·결정론·조문 인용). 미검증 수치 금지.
- **README 첫 단락**: 한 줄 + 면책 유지. 현행 README의 기조(결정론 우선·무LLM·면책)와 이미 정합 — 바꿀 때 이 문서 기준으로.
- **랜딩 히어로**: 한 줄 + "무료 IP당 50콜/일" 같은 실측 한도만. 랜딩↔라이브 불일치는 반려 사유(회사 원칙) — 라이브에 없는 기능·수치 금지.
- **블로그 톤**: §2 실무 장면에서 출발(담당자의 하루 → 대체재의 한계 채록 → 도구가 주는 것). 대체재 비방 금지 — §3의 관찰된 한계만 서술. "검증됨"·체감 수치 창작 금지. 평범한 AI 글 반려 기준 적용(고유 데이터 각도 = §2·§3의 채록).
